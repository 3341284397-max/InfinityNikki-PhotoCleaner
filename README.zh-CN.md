## 它解决什么问题

游戏内删除照片，删掉的往往只是相册里的引用，本地文件仍然留在 `ScreenShot` 目录里。
时间一长，这个目录会堆满「游戏里根本看不到」的照片，占着几个 G 的空间，又不敢手动删——
因为你分不清哪张还在用、哪张已经废弃。

这个工具做的就是把这件事**变得可以分辨**：告诉你哪些照片游戏里已经没有了，并把它们挪到一边，
最后由你自己按 Delete。

## 四种判定 + 两种标记

**判定**是程序对照片下的结论，**标记**是你贴上去的标签。两者是**两列，不是一回事**：
同一张照片可以既判成「已删除」、又被你标成「已忽略」，列表里就并排显示
`已删除` `已忽略`。

| 判定 | 含义 | 颜色 |
|---|---|---|
| **在册** | 文件名仍出现在游戏的相册缓存里，游戏内可见 | 绿 |
| **已删除** | 曾经在相册里出现过，现在相册缓存里已经没有了 | 赭红 |
| **疑似** | 相册缓存里没有，工具也从没见过它（旧照片，或新装工具后的首次扫描） | 琥珀 |
| **太新** | 属于「已删除 / 疑似」，但修改时间不足 3 天——刚截的图不参与判定，避免误伤 | 灰 |

| 标记 | 谁来贴 | 含义 |
|---|---|---|
| **已忽略** | 你 | 这张不用管，不参与勾选、统计与移动。随时可取消 |
| **外部导入** | 工具自动 | 文件是拷进来的，不是游戏截的（创建时间明显晚于修改时间） |

判定依据来自两处：

- **相册缓存名单**：`X6Game/Saved/GamePlayPhotos/*/NikkiPhotos_*` 下的文件名
- **本地台账**：工具自己记的 `album-ledger.tsv`，记录「这张照片曾经在册」

「已删除」需要**曾经在册、现在不在**两个条件同时成立。**任何一张都不会被默认勾选**——
勾选永远是你的动作，工具不替你做决定。

**标记不会改写判定。** 取消「已忽略」之后，照片直接回到它本来的判定
（在册就回在册、太新就回太新），不需要重新扫描，也不会掉进「已删除」。

## 工作原理

### 一次扫描到底做了什么

工具只读两处、不写游戏目录：**相册缓存里的文件名**，和 `ScreenShot` 目录里的文件。然后对每个本地文件问三个问题：

```
X6Game/ScreenShot/xxx.jpeg
  │
  ├─ ① 文件名在相册缓存里？──── 在 ──→ 【在册】游戏里还看得见，不动它
  │
  └─ 不在 ↓
       ├─ ② 台账记过「它曾经在册」？── 记过 ──→ 【已删除】
       │                                     游戏里删了，本地还留着
       └─ 没记过 ↓
            └─→ 【疑似】工具没见过它，可能删过、也可能还没同步
```

第三个问题（是否「太新」）在①②之后叠加：只要不在相册里，且文件修改时间不足 3 天，一律降级成「太新」暂不处理。

### 台账：为什么第一次用一张都勾不出来

判断「游戏里删了」的唯一依据是**对比**：它以前在相册里，现在不在了。可第一次运行时，工具还没见过任何照片，没有「以前」。

所以首次扫描只做一件事——**建档**。它把当前在相册里的照片记进 `相册台账.tsv`（文件名、首次见到、最后见到、文件大小），这一轮所有「相册里没有」的照片只能是「疑似」。

去游戏里删几张，回来点「重新扫描」，那时台账里已经有记录了，才会出现「已删除」。

**台账里还存了文件大小。** 因为硬盘上的文件名可能被复用：一张「已删除」的照片被同名新截图顶替时，新文件大小几乎一定不同。工具发现大小对不上，就把旧档案作废、当新文件重新判断——否则新照片会白捡一条「曾经在册」的记录，被判成「已删除」然后被你一键移走。

### 外部导入：从 U 盘拷回来的照片

如果你把历史备份拷回 `ScreenShot`，它们的文件名和台账里一模一样，会被判成「已删除」——但它们其实是你在游戏里**从未删过**的照片（游戏里压根没这些记录，或者你早就删了相册引用但备份还在）。

工具用**时间戳**把它们挑出来：

> 游戏截图是「写完即定稿」——创建时间和修改时间几乎相同。
> 从 U 盘 / 网盘 / 另一台机器拷进来的文件，**修改时间保留原值，创建时间变成拷贝那一刻**。

于是 `创建时间 − 修改时间 > 1 小时` 就判为「外部导入」。这个判据是单边的：拷入只会让创建时间晚于修改时间；用图片软件改图则是修改时间变新，方向相反，不会误中。

「外部导入」是**标签**，不覆盖原判定。列表里会同时显示「已删除」和「外部导入」徽章——你需要同时知道「它本来会被判成什么」和「为什么被排除」。这类照片默认不勾选、不计入待删统计、不会被「全选」选中。

判据不完美：某些拷贝工具或 FAT32 直接移动会保留创建时间，那时它会漏判。这就是手工标记存在的理由。

### 手工标记：程序猜不准的时候

工具栏的「标记忽略」给用户一个最终裁决权。被标记的照片**多一个「已忽略」标签**，
判定原样保留（列表里两列并排：`已删除` `已忽略`），**不参与勾选、统计、移动**；
「取消忽略」随时去掉标签，照片立刻回到原来的判定，不用重新扫描。

标记存在 `用户标记.tsv` 里，和台账分开——台账是「程序观察到的事实」（可以整份删掉重建），标记是「你说的话」（只有你能改）。key 用**文件名 + 文件大小**：同名但大小变了，说明硬盘上已经是另一张照片，旧标记不会套到它头上。这个方向是安全的——宁可漏掉一条忽略，也不要误忽略一张本该清理的照片。

每次改动前，上一版会自动存成 `用户标记.tsv.bak`，标错了还能捡回来。

### 待清理文件夹：搬出去的还能拿回来

列表上方有两个胶囊：`游戏截图` 和 `待清理`，点一下就换一个文件夹看。
待清理视图用的是**同一张列表、同一个预览区**，只是数据来自 `无限暖暖清理助手_待清理照片`：

- 能看到搬出去的每一张，能双击看大图，能像看截图目录那样勾选
- 勾好之后，底部主按钮变成「移回原目录（N）」，按勾选**逐张**搬回去
- 原目录里已经有一份同名同大小的，跳过不重复搬；同名但内容不同的，改名保留两份
- 搬回去的同时从移动记录里划掉，所以「移回原目录」那条整批还原的老入口不会重复搬
- 待清理文件夹搬空了会自动删掉，不在 `ScreenShot` 里留空壳

这个视图里没有「判定」也没有「标记」可言（照片已经不在截图目录里了），
所以标记类按钮会置灰 —— 不是坏了，是这里没有可标记的对象。

![待清理视图](docs/screenshots/pending-zh.png)


### 这个程序永远不会做的事

- **不删文件。** 代码里没有删除照片的语句，「移动」就是 `File.Move`。真正的删除永远由你在资源管理器里按 Delete。
- **不联网。** 没有任何网络请求，没有账号、没有统计。
- **不猜。** 判不准的一律交给「疑似」，且「疑似」永远不自动勾选。

## 运行环境

三种形态，任选一种，都不需要装运行库。

| 形态 | 系统要求 | 依赖 |
|---|---|---|
| **exe 版**（推荐） | Windows 10 version 1903 及以上 / Windows 11，64 位 | .NET Framework 4.8，**Win10 1903 起系统自带**，无需另装 |
| **PowerShell 版** | Windows 10 / 11 | **零依赖**，只用系统自带的 PowerShell 5.1 |
| **网页版** | Chrome / Edge 86+ 桌面版 | 无。浏览器本地读取文件夹，不装任何东西 |

分辨率：窗口默认 1180×780，支持 100% / 125% / 150% 缩放，窗口会按 DPI 同比放大。

### 关于未签名程序

exe 没有代码签名，Windows 可能以两种方式拦截，处理办法不同：

| 拦截方式 | 出现在 | 现象 | 怎么办 |
|---|---|---|---|
| **SmartScreen** | Win10 / Win11 都有 | 「Windows 已保护你的电脑」 | 点「更多信息」→「仍要运行」 |
| **智能应用控制（SAC）** | 仅 Win11 全新安装默认开启 | 直接拒绝，**没有放行按钮** | 改用 PowerShell 版或网页版 |

**为什么不做代码签名。** SAC 只信任链接到 Microsoft Trusted Root Program 中 CA 的证书，
而且这个判断在云端完成，不采信本机证书存储 —— 所以**自签名证书（免费）对 SAC 完全无效**，
手动把根证书装进「受信任的根证书颁发机构」也不行。真正有效的选项：

| 方式 | 费用 | 个人开发者可用性 |
|---|---|---|
| Azure Artifact Signing（原 Trusted Signing） | $9.99/月 | 个人仅限美国、加拿大 |
| OV / EV 代码签名证书 | $150–400/年 | 需实名验证与硬件 token，有效期最长 460 天，到期需续费重签 |
| Microsoft Store 上架 | $19 一次性 | 微软代为签名，完全绕过两种拦截 |

对一个免费开源的小工具来说这个代价不成比例，因此本项目选择不签名，
改为提供**零依赖的 PowerShell 版**作为稳妥的替代路径。

> Windows 10 没有 SAC 这个功能，Win10 用户只会遇到上面第一种情况。

## 三种用法

### 1. exe 版

1. 下载 `NikkiPhotoCleaner.exe`，放到任意位置双击运行
2. 点「重新选择」，选 `X6Game\ScreenShot` 目录（选游戏根目录也行，会自动找）

4. 核对默认勾选的「已删除」项。列表上方有 `已勾选 N / M 张` 和「全选」按钮，
   一次勾上百张不用挨个点；键盘 `Ctrl+A` 同样管用
5. 点「移入待清理文件夹」，照片被**移动**（不是删除）到一个独立文件夹
6. 打开那个文件夹，确认无误后自己删

移动前会弹一个确认窗口，把要动的每一张都列出来（列表可滚动，几百张也是全列）：

![确认移动](docs/screenshots/move-zh.png)

没有游戏目录也可以点「先看演示」，或者带 `?demo=1` 参数打开。

![网页版](docs/screenshots/web-zh.png)

浏览器出于安全不允许网页直接移动本地文件，所以这一步交给你确认一次。

**① 下载脚本，双击运行**（最省事）
得到一个几 KB 的 `.bat`。把它拖进 `X6Game\ScreenShot` 双击即可；
如果先在弹窗里填了截图文件夹的完整路径，脚本放在哪儿都能直接跑。

**② 复制命令，粘进命令行窗口**（脚本被安全软件拦时用这个）

每张照片是一条 `if exist … move …`，撞名改 `_1`、不覆盖；开头 `chcp 936` 保证中文路径不乱码。

**③ 复制提示词，交给你的 AI 助手**（兜底）
把弹窗里那段提示词给能操作文件的助手（Copilot、Claude、ChatGPT 之类）。

三条路的产物，都可以先展开「先看看脚本长什么样」核对一遍再动手。

![移动照片](docs/screenshots/web-script-zh.png)

几个细节：

- **为什么要你填路径**。浏览器不会把文件夹路径告诉网页，只能拿到文件夹名字。
  在弹窗里粘一次完整路径（在资源管理器地址栏点一下就能复制），之后会记住 ——
  脚本和命令据此直接定位，不用再拖文件夹
- 脚本会先在自己旁边、以及自己旁边的 `ScreenShot\` 里找一张清单里的照片。
  找到了就直接开工；找不到才让你把文件夹拖进窗口
- 原位置已经没有的照片算「跳过」，不算失败；一张都没移动成功时不会留下空文件夹

  实测会把「要不要删掉自己」当成命令执行

  可能连「仍要运行」都不给 —— 这不是脚本内容的问题（它就是几十行 `move`），
  是这个扩展名天生不招人待见。绕过去最省事的是上面第 ② 条：命令不落盘，没东西可拦。
  兜底还有第 ③ 条和 exe 版

> 如果你更想「点一下就移动完」，用 exe 版：它直接在本地移动，还能一键还原。
> 网页版的价值是不装任何东西、也不会有未签名程序被 SAC 拦的问题。

## 安全边界

这个工具被设计成「即使误操作也丢不了照片」：

- **不删除**。全流程没有任何删除照片的代码路径，移动也只是 `File.Move`
- **可还原**。每次移动都写一份 `最近一次移动记录.txt`，记下源目录和目标目录，
  「移回原目录」按它还原
- **清理记录不碰照片**。「清理记录」只清工具自己生成的缩略图缓存、报告、台账，
  危险项（台账、还原记录）默认不勾，勾了还要二次确认
- **不联网**。全程本地读写，不上传任何数据，不需要账号
- **数据目录独立**。所有中间文件都放在 `无限暖暖清理助手_使用数据` 里，不污染游戏目录

## 数据都放在哪

**第一次启动先问你一件事：游戏的照片在哪。**

程序要靠这个目录才知道「哪些截图已经进了游戏相册」，也才算出「把使用数据放到游戏旁边」
是哪一级。自动探测到的路径只会**预填**在框里 —— 点「就用这个」才算数。
以前是探到就直接用，用户既不知道程序读了哪个文件夹，也没机会纠正。

不想现在选就点「先跳过」：程序照常打开，主界面提示「还没指定游戏照片文件夹」，
右上角「重新选择」随时能补。这时候**不会**再问数据位置 —— 没有路径就推不出推荐位。

![先确认游戏照片在哪](docs/screenshots/game-zh.png)

确认之后才问第二个问题：

| 选项 | 数据落在 |
|---|---|
| 搬到游戏旁边（推荐） | 截图目录 `<…>\InfinityNikki\X6Game\ScreenShot` 中，取名 `InfinityNikki` 的那一级的**父目录**（通常是 `InfinityNikki_APP`），和 `InfinityNikki` 文件夹并列 |
| 先不动它 | 保持现状（exe 所在目录） |
| 我自己选一个位置 | 任意目录 |

选「搬过去」会走和「更改位置」同一套流程：复制 → 核对文件数与总字节 → 删掉旧文件夹。

推荐位怎么算：先找路径里名叫 `InfinityNikki` 的那一段，取它的父目录；
自定义安装（`D:\Games\X6Game\ScreenShot`）没有这一段，退一步取 `X6Game` 的上一级。
游戏直接装在盘根（`D:\InfinityNikki\…`）时这两级都不是合适位置，
那就干脆不给推荐，只留「先不动它 / 我自己选」。

选择结果记在 `%APPDATA%\NikkiPhotoCleaner\location.txt`。
为什么记在那儿而不是数据目录里：数据目录的位置本身就是被记录的东西，记在里面等于自指。

老用户**不会看到这两个窗口** —— 已经记过游戏目录的、数据文件夹在 exe 旁边已经存在的，
都直接沿用。

![确认照片目录之后，再问数据位置](docs/screenshots/data-zh.png)


在数据目录之下：

| 内容 | 中文界面 | 英文界面 |
|---|---|---|
| 数据目录 | `无限暖暖清理助手_使用数据` | `NikkiCleaner_Data` |
| 待清理文件夹 | `无限暖暖清理助手_待清理照片` | `NikkiCleaner_ToDelete` |
| 相册台账 | `相册台账.tsv` | `album-ledger.tsv` |
| 用户标记 | `用户标记.tsv`（改前自动存 `.bak`） | `user-marks.tsv` |
| 网页报告 | `网页报告/` | `reports/` |
| 设置 | `设置.txt` | `settings.txt` |
| 移动记录 | `最近一次移动记录.txt` | `last-move.txt` |

**目录名在程序启动时锁定一次**：只看「已经存在哪一个」。
所以中途切换界面语言**不会**新建另一套目录，台账和还原记录不会断链。
如果两个目录都存在（旧版本升级上来的情况），中文目录优先。

### 改位置、删数据、卸载

右上角「数据位置」里有三个动作：

- **打开**：在资源管理器里定位当前数据文件夹
- **更改位置**：复制到新位置 → **核对文件数与总字节** → 删掉旧文件夹。
  核对不上就一个文件都不删，宁可失败也不让你只剩半份数据；
  旧文件夹如果还有文件被别的程序占着，会登记下来，下次启动第一件事补删。
  目标位置已经有数据目录时直接拒绝 —— 两份台账混在一起会把「已删除」判断搞乱
- **删除使用数据**：把文件夹**整个删掉**（连文件夹本身，不只是里面的文件），
  连 `%APPDATA%` 里那条位置记录一起清掉，然后**程序退出**。
  下次启动会重新建一份、并在定位到游戏后再问你要不要搬 —— 能再看到那个弹窗，
  就说明上一份确实删干净了。照片不动；待清理文件夹里还有照片时会单独提醒

![数据位置](docs/screenshots/data-manage-zh.png)

为什么删数据要退出程序：文件被自己占着就删不干净。旧版本删完之后主窗口又扫了一次，
扫描第一件事就是写台账，于是文件夹原地重建、只剩一份空台账 ——
看着像「删了但没删干净」。现在删完直接退出，不留这个后手。

这个程序没有安装过程，所以**没有卸载程序**。要彻底清理，两个办法：

1. 点「删除使用数据」（会连数据文件夹和位置记录一起清掉并退出），再删掉 exe
2. 手动删三处：数据文件夹、待清理文件夹、`%APPDATA%\NikkiPhotoCleaner\location.txt`

忘了数据在哪？重下一份 exe 跑一次、点「数据位置」就能看到完整路径。

## 已知限制

- 判定依赖游戏的相册缓存结构（`Saved/GamePlayPhotos/*/NikkiPhotos_*`）。
  游戏大版本更新若改动该结构，需要相应调整扫描逻辑
- 相册缓存里的文件名与本地文件按文件名匹配。若游戏内改名，会判为「疑似」
- 网页版本身不能移动文件（浏览器沙箱限制），只能生成脚本 / 命令 / 提示词，由你在本地执行；
  这三条路都没有「还原」功能，想撤销请用 exe 版或 `src/scripts` 里的脚本
- 只在 Windows 上验证过
